# 2026-08-29 18:17 BIOS 1.3.1 → 1.8.2

**状態:** 適用済み(再起動して反映確認済み)

## 内容

`fwupd` (LVFS経由) で Dell XPS 14 DA14260 のシステムファームウェアを更新。

```bash
fwupdmgr refresh
fwupdmgr get-updates
fwupdmgr update      # ← 実際の書き込み。AC接続必須
```

| | 更新前 | 更新後 |
|---|---|---|
| BIOS | 1.3.1 (2026-02-12) | **1.8.2 (2026-05-22)** |
| BIOS同梱マイクロコード | 0x115 | **0x11b** |
| 実効マイクロコード | 0x11c | 0x11c(変化なし) |

Dell のリリースノート(1.8.2):

- Dell Security Advisory のセキュリティ修正
- BIOS Setup に Connected Service Delivery オプションを追加
- **Intel の best-known configuration に合わせてファームウェアを更新**

中間リリース 1.5.1 (2026-04-01) は「Early Keyboard Backlight の既定値をオフに変更」のみ。

## 理由

XPS 14 のハードロックアップ調査。ソフトウェア側の調査が行き詰まり、
プラットフォーム側の疑いが相対的に上がったため
(ソフトロックアップ検知が有効でも発火しない = 割り込みごと停止している)。

BIOS が半年前のもので、Panther Lake という枯れていない世代において
「Intel推奨構成に追従」という記述があったこと、また仮に効かなくても
**最新BIOSであることは以後の切り分けおよびDellへの問い合わせの前提条件**になるため。

変更履歴にハング・フリーズの修正は明記されていない。期待値は高くない。

## 事前検証(適用可能かの裏取り)

`fwupdmgr get-devices` で以下を確認してから実行した。

- `Dell Inc. XPS 14 DA14260` として正しく認識
- `System Firmware` エントリが存在し `アップデート可能` フラグあり
- **`アップデートステータス: 成功`** — この個体で過去にカプセル更新が成功した実績
- `リモートサーバーに登録されています` (LVFS登録済み)
- `/sys/firmware/efi/esrt/` が存在しエントリ2件(ファームウェアがカプセル更新に対応)

## 元に戻す方法

**BIOSのダウングレードは原則行わないこと。**
`最小バージョン: 1.0.0` なので技術的には可能だが、リスクに見合わない。
問題が出た場合はDellサポートへ。

## 検証方法

```bash
cat /sys/class/dmi/id/bios_version   # 1.8.2 (root不要)
cat /sys/class/dmi/id/bios_date      # 05/22/2026
fwupdmgr get-updates                 # 「アップデートはありません」
```

## 注意: UCSI警告は指標にならない

更新前に毎ブート出ていた以下の警告は、更新後のブートでは出ていない。

```
ucsi_acpi USBC000:00: con2: Firmware bug: duplicate partner altmode SVID 0x8087 ...
ucsi_acpi USBC000:00: con2: VDO mismatch: 0x8087a843 vs 0x04000001
```

**ただしこれをBIOS更新の効果と解釈してはいけない。**
BIOS 1.3.1 のままだった 2026-08-29 17:22 のブートでも、ドック接続済みで警告0件だった。
同一BIOSでもブートごとに出たり出なかったりするため、指標として使えない。
