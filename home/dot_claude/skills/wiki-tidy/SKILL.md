# wiki-tidy

最初に `~/.claude/issue-flow/conventions.md` を読み(特に §5)、§0 の `check.sh` を実行する。

## 手順

1. `sh ~/.claude/issue-flow/scripts/wiki-path.sh` で作業コピーを得て、全ページを読む

2. 問題を洗い出す:
   - **索引**: `Home`(と `_Sidebar`)に載っていないページ、載っているのに存在しないページ
   - **重複・矛盾**: 同じ話題が複数ページに散っている、記述が食い違っている
   - **古い記述**: 参照しているファイルパス・関数がリポジトリにもう無い、
     出典の ISSUE が「not planned」で閉じられた、Roadmap の「やらないこと」と矛盾する
   - **置き場所違い**: ISSUE 1件でしか意味の無い内容(本来は ISSUE 本文に書くもの)、
     ISSUE 単位で作られたページ(話題単位に組み替える)
   - **出典の欠落**: 出典 ISSUE の URL が付いていない記述、`#123` だけでリンクになっていないもの
   - **公開範囲**: PUBLIC リポジトリで識別子や生のログが書かれていないか

   ファイルパスの存在は `git ls-files` や `test -e` で、ISSUE の状態は `gh issue view` で確かめる

3. 直す:
   - 索引の更新、リンク・出典の修正、表記ゆれの統一、小さな統合は自律で行ってよい
   - **ページの削除・大きな統合・内容の削除**は、何をどこへ移すか・何を消すかを
     一覧にしてユーザーに確認してから行う
   - 古い記述は黙って消さず、正しい内容に直すか、直せなければユーザーに確認する
   - 統合で消えたページ名へのリンクが他のページに残らないようにする

4. commit・push する(`docs` 方式なら commit のみ)。コミットメッセージに整理の内容を書く

5. 変更報告(conventions.md §9)を出す。直さなかった指摘(要判断のもの)も併せて列挙する。
