# 全プロジェクト共通の作業ルール

dotfiles(chezmoi)から全マシンに配布している。リポジトリごとの CLAUDE.md が
これと食い違う場合は、リポジトリ側を優先する。

## Git

- コミットメッセージは日本語。1行目は `feat:` / `fix:` / `docs:` / `refactor:` / `chore:`
  などの接頭辞 + 変更内容の要約。本文には「なぜ」を書く
- 対応する ISSUE があるときは、メッセージに `#123` の形で番号を含める
  (閉じるなら `Closes #123`)。対応する ISSUE が無ければ書かない
- コミットはユーザーが求めたとき、または承認された計画に含まれるときだけ行う
- **push・マージ・PR のクローズはユーザーが明示的に求めたときだけ。**
  公開が起きるのは push の時点なので、コミットだけで止めて報告する
- 既定ブランチ上で作業を始めるなら、先にブランチを切る

## 権限・認証

- `sudo` が要る作業はユーザーが実行する。コマンドを提示して結果を受け取る
- **`gh auth` 系(login / refresh / token / switch)は実行しない。** スコープの追加や
  アカウントの切り替えはユーザーの判断で、`! gh auth ...` として本人が実行する
  (settings.json の deny でも禁止している)
- 秘密(鍵・トークン・パスワード・`.env`)を読まない・書かない・コミットしない

## 機密情報・個人情報の出力

- 会話の返答・ツールの説明文・コミット・ISSUE などに、機密情報と**個人情報**を出力しない。
  個人情報: 氏名・メールアドレス・住所・電話番号・アカウント ID・トークンの一部、など
- コマンドの出力に含まれていたら、そのまま貼らずに伏せる(例: `account ***`)。
  必要なら「含まれていた」ことだけを伝える
- 作業に本当に必要な場合は、出力する前にユーザーに確認する

## 返答

- **簡潔に。** 結論を先に、必要なことだけを書く。経緯・言い換え・繰り返しは省く
- 表や箇条書きは、本当に整理が要るときだけ使う

## 公開リポジトリ

- 書き込む前に `gh repo view --json visibility` で公開範囲を確認する
- PUBLIC のリポジトリ・ISSUE・PR・Wiki に、ホスト名・IP アドレス・ユーザー名・
  シリアル番号・ログやダンプの生の貼り付けを書くときは、何が露出するかを説明して確認を取る

## 作業の進め方

- 既存の関数・スクリプト・仕組みを探して再利用してから、新しく書く
- 外部ツールのオプションや設定キーは、記憶で書かずに `--help`・ドキュメント・
  実物で確認してから使う
- 検証できたことと、できなかったこと(権限不足で未実行など)を分けて報告する
